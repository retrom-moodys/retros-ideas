# GROUND RULES — Exoplanets Design Practice

*Working agreements between the user and the agent for this data-storytelling
practice. First created 2026-08-31. These govern how we work, not what we conclude.*

---

## 1. Audience & explanation level (set once, honored throughout)

- **Audience:** curious, educated *general public* — science-explainer / museum-panel /
  newsroom-graphic readers.
- **Explanation level:** plain language, **no astrophysics assumed**. Always anchor
  abstract quantities to things people know (Earth, Jupiter, "a 5-day year").
- If a design would only land for domain experts, that's a signal it's the wrong design
  for this audience — flag it.

## 2. Design before code

- Stay in **design mode** until the user explicitly says to build.
- `RESEARCH.md` (the brief) is **committed before any code** is written.
- "Rough it to test a design question" is still design — a throwaway sketch to answer
  *does this read?* is allowed and encouraged; polished implementation is not.

## 3. Explore before choosing

- Put **at least 2 (ideally 3+) distinct concepts** on the table before picking one.
- Document the **alternatives rejected and why** — a decision without its discards is
  half a decision.

## 4. Restate the goal before proposing

- Before any final design proposal, **restate the goal in one sentence** so we're
  aligned on what success means. Misalignment is cheapest to fix here.

## 5. Reverse Direction (mandatory check)

- Before locking a design, run **at least one Reverse Direction pass**: argue the
  strongest case *against* the chosen direction — wrong story, wrong chart, audience
  won't get it — and either defend with a mitigation or change course.
- The point is to earn the decision, not rubber-stamp it.

## 6. Honesty about the data

- Blanks are **unknown, not zero**.
- Never let a chart imply more than the data supports (e.g. detectability ≠ rarity;
  equilibrium temperature ≠ habitability).
- State what a visualization **cannot** show, especially when absence is the message.

## 7. Takeaway lives in the words

- The main insight goes in the **title/subtitle**, not buried in a legend. If the
  viewer needs the legend to get the point, the design isn't done.

## 8. Traceability

- Every design claim should trace to a number we actually pulled from the data, not a
  remembered "fact." When unsure, profile it.
